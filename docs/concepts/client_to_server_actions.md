# A2UI 클라이언트-서버 액션

A2UI의 상호작용은 양방향 통신 루프에 의존합니다. 에이전트가 컴포넌트와 데이터 업데이트를 스트리밍하면서 UI를 주도하는 동안, 클라이언트는 **액션(Actions)** 과 **데이터 모델 동기화**를 통해 사용자 의도를 에이전트로 다시 전달합니다.

## 액션 아키텍처

액션은 UI 컴포넌트가 동작을 트리거할 수 있게 합니다. `Action` 스키마에 정의되며, 크게 두 가지로 나뉩니다.

1. **서버 이벤트**: 에이전트로 전달되어 처리됩니다. 예: "제출" 클릭
2. **로컬 함수 호출**: 클라이언트에서만 실행됩니다. 예: URL 열기

### 스키마에서의 연결

`Button` 같은 컴포넌트는 `action` 속성을 노출합니다. 서버 이벤트 연결 예시는 다음과 같습니다.

```json
{
  "id": "submit-btn",
  "component": "Button",
  "child": "btn-text",
  "action": {
    "event": {
      "name": "submit_reservation",
      "context": {
        "time": { "path": "/reservationTime" },
        "size": { "path": "/partySize" }
      }
    }
  }
}
```

- **`name`**: 에이전트가 분기 처리할 안정적인 식별자입니다.
- **`context`**: 키-값 쌍의 맵입니다. 값은 리터럴이거나 현재 데이터 모델 상태에서 값을 가져오는 `path`일 수 있습니다.

> **참고**
>
> 데이터 모델은 서피스의 전체 상태 트리이고, 액션의 `context`는 그중 필요한 부분만 골라낸 "뷰"에 가깝습니다. 이렇게 하면 에이전트가 거대한 상태 트리를 직접 탐색하지 않아도 됩니다.

### 로컬 액션과 서버 이벤트

서버 이벤트가 에이전트와 상호작용하는 핵심 방식이지만, **로컬 액션**은 네트워크 왕복 없이 클라이언트에서 즉시 동작해야 할 때 유용합니다.

```json
{
  "id": "help-btn",
  "component": "Button",
  "child": "help-text",
  "action": {
    "functionCall": {
      "call": "openUrl",
      "args": { "url": "https://a2ui.org/help" }
    }
  }
}
```

로컬 액션의 대표적인 용도는 다음과 같습니다.

- 제출 전에 폼 입력값 검증
- 로컬 표시 값 포맷팅

### 기본 카탈로그 액션 검증

기본 카탈로그는 클라이언트에서 실행 가능한 제한된 체크(check) 집합을 정의합니다. 대화형 컴포넌트는 `checks` 목록을 가질 수 있고, 버튼의 경우 체크에 실패하면 클라이언트에서 자동으로 비활성화됩니다.

이 체크는 잘못된 상호작용을 사전에 막는 **UI 상태**를 다루는 것이며, 서버에서 여전히 수행되어야 하는 **데이터 무결성** 검증을 대체하지 않습니다.

## 로컬 상태 업데이트와 쓰기 계약

액션이 전송되기 전에 이미 클라이언트는 UI 상태를 로컬에서 관리하고 있습니다. A2UI는 `TextField`, `CheckBox`, `Slider` 같은 입력 컴포넌트에 대해 **읽기/쓰기 계약(Read/Write Contract)** 을 정의합니다.

1. **읽기(Model → View)**: 컴포넌트가 렌더링될 때 바인딩된 `path`에서 값을 읽습니다.
2. **쓰기(View → Model)**: 사용자가 입력하거나 체크하면 클라이언트가 새 값을 로컬 데이터 모델에 즉시 씁니다.

즉, 로컬 모델은 항상 UI의 현재 상태에 대한 진실의 원천입니다. 사용자가 버튼을 눌러 액션을 트리거하기 전까지는 이 동기화가 완전히 클라이언트 안에서 일어납니다.

> **중요**
>
> 로컬 모델 업데이트는 동기적입니다. 따라서 액션이 `context` 경로를 해석하거나 `DataModelSync` 페이로드를 포장하기 전에 데이터 모델이 완전히 갱신됩니다.

이 방식은 네트워크 디바운싱을 직접 구현할 필요를 줄이고, 사용자가 `TextField`에 입력하는 동안 지연으로 인한 흔들림을 크게 줄여 줍니다.

### 폼 제출 패턴

이 분리 덕분에 견고한 폼 제출 패턴을 만들 수 있습니다.

- `TextField`가 `/reservationTime`에 바인딩됩니다.
- 사용자가 `"7:00 PM"`을 입력하면 로컬 모델의 `/reservationTime`이 즉시 갱신됩니다.
- 사용자가 `"Book"` 버튼을 누르면 버튼 액션이 로컬 모델의 `path: "/reservationTime"`을 해석해 현재 값을 서버로 보냅니다.

## 사용자 상호작용 흐름

사용자가 컴포넌트와 상호작용하면:

1. 클라이언트가 로컬 **데이터 모델**에서 `context`의 모든 `path` 참조를 해석합니다.
2. 클라이언트가 `client_to_server.json` 형식에 맞는 액션 페이로드를 만듭니다.
3. 선택된 전송 계층(A2A, WebSockets 등)을 통해 서버로 전송합니다.

### 예시: 액션 페이로드(v0.9)

데이터 모델에 `{"reservationTime": "7:00 PM", "partySize": 4}`가 들어 있는 상태에서 사용자가 버튼을 클릭하면, 클라이언트는 다음과 같이 보냅니다.

```json
{
  "version": "v0.9",
  "action": {
    "name": "submit_reservation",
    "surfaceId": "booking-surface",
    "sourceComponentId": "submit-btn",
    "timestamp": "2026-02-25T10:40:00Z",
    "context": {
      "time": "7:00 PM",
      "size": 4
    }
  }
}
```

> **버전 참고**
>
> v0.8에서는 최상위 키가 `userAction`이었습니다. v0.9에서는 위 예시처럼 더 단순한 `action` 키로 바뀌었습니다. 표준 프로토콜 파서는 페이로드에 선언된 버전에 해당하는 키를 기대합니다.

## 에이전트 처리

에이전트(또는 오케스트레이터)가 이 이벤트를 받아 처리합니다. 에이전트 시스템에서는 보통 이 이벤트를 LLM용 내부 사용자 질의로 변환합니다.

```python
if action_name == "submit_reservation":
    time = context.get("time")
    size = context.get("size")
    query = f"User submitted a reservation for {size} people at {time}."
    response = await llm.generate(query)
```

## 클라이언트-서버 오류 보고

사용자 액션 외에도 클라이언트는 `error` 페이로드를 사용해 시스템 수준 오류를 서버로 보낼 수 있습니다.

### 검증 실패

에이전트가 카탈로그 스키마나 프로토콜 규칙을 위반하는 A2UI JSON을 보내면, 클라이언트는 `VALIDATION_FAILED` 오류를 보냅니다.

```json
{
  "version": "v0.9",
  "error": {
    "code": "VALIDATION_FAILED",
    "surfaceId": "booking-surface",
    "path": "/components/0/children",
    "message": "Expected array of strings, got null."
  }
}
```

에이전트는 이 오류를 받아 수정하거나, 내부적으로 보정한 뒤 수정된 UI를 다시 보낼 수 있습니다.

## 데이터 모델 동기화(v0.9)

v0.9에서는 강력한 "상태 비저장(stateless)" 동기화 기능이 도입되었습니다. 클라이언트가 서버로 보내는 모든 메시지의 메타데이터에 해당 서피스의 **전체 데이터 모델**을 자동으로 포함할 수 있습니다.

### 동기화 활성화

서피스 초기화 시 에이전트가 동기화를 요청합니다. `createSurface` 메시지에서 `sendDataModel: true`를 설정하면, 클라이언트는 동기화 루프를 시작합니다.

### 와이어 상의 동작

동기화가 켜지면 클라이언트는 데이터 모델을 별도 메시지로 보내지 않습니다. 대신 A2A 메시지 같은 전송 봉투의 **메타데이터**에 붙입니다.

### 왜 데이터 모델 동기화를 쓰나요?

- 더 단순한 연결
- 상태 비저장 에이전트
- 음성이나 텍스트 같은 verbal shortcut 지원

## 클라이언트 메타데이터와 기능

에이전트가 UI를 안전하게 보내려면 클라이언트가 어떤 컴포넌트 카탈로그를 지원하는지 먼저 광고해야 합니다. 이는 `a2uiClientCapabilities` 객체로 처리합니다.

### 기능 광고

클라이언트는 서버로 보내는 메시지의 메타데이터에 `a2uiClientCapabilities` 객체를 포함합니다.

### 왜 필요한가요?

이 핸드셰이크가 없으면 에이전트는 렌더러가 특정 컴포넌트를 실제로 처리할 수 있는지 확신할 수 없습니다.

## 전송 및 인코딩

A2UI는 전송 방식에 종속되지 않지만, 일반적으로 A2A 또는 WebSockets 위에서 사용됩니다. 페이로드가 어떤 식으로 감싸이는지 이해하는 것이 구현에 중요합니다.
