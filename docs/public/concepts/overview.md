# 핵심 개념

이 섹션에서는 A2UI의 기본 아키텍처를 설명합니다. 이 개념들을 이해하면 효과적인 에이전트 주도 인터페이스를 설계하는 데 도움이 됩니다.

주요 용어에 대한 짧은 정의는 [Glossary](glossary.md)를 참고하세요.

## 큰 그림

A2UI는 세 가지 핵심 아이디어를 중심으로 구성됩니다.

1. **스트리밍 메시지**: UI 업데이트는 에이전트에서 클라이언트로 JSON 메시지 시퀀스로 흘러갑니다.
2. **선언적 컴포넌트**: UI는 코드가 아니라 데이터로 설명됩니다.
3. **데이터 바인딩**: UI 구조는 애플리케이션 상태와 분리되어 있어 반응형 업데이트가 가능합니다.

## 주요 주제

### [데이터 흐름](data-flow.md)
메시지가 에이전트에서 렌더링된 UI까지 이동하는 방식을 다룹니다. 레스토랑 예약 흐름의 전체 생명주기 예시, 전송 옵션(SSE, WebSockets, A2A), 점진적 렌더링, 오류 처리까지 포함합니다.

### [컴포넌트 및 구조](components.md)
A2UI의 **인접 리스트 모델**을 사용해 컴포넌트 계층을 표현하는 방식을 설명합니다. 평면 리스트가 중첩 트리보다 왜 유리한지, 정적 자식과 동적 자식을 어떻게 사용하는지, 증분 업데이트 베스트 프랙티스가 무엇인지 살펴봅니다.

### [데이터 바인딩](data-binding.md)
JSON Pointer 경로를 사용해 컴포넌트를 애플리케이션 상태에 연결하는 방법을 설명합니다. 반응형 컴포넌트, 동적 리스트, 입력 바인딩, 그리고 구조와 상태를 분리하는 이유를 다룹니다.

## 메시지 유형

=== "v0.9 (안정판)"

    - **`createSurface`**: 새 서피스를 만들고 카탈로그를 지정합니다.
    - **`updateComponents`**: 서피스의 UI 컴포넌트를 추가하거나 업데이트합니다.
    - **`updateDataModel`**: 애플리케이션 상태를 업데이트합니다.
    - **`deleteSurface`**: UI 서피스를 제거합니다.

    v0.9에서는 서피스 생성과 렌더링이 분리됩니다. `createSurface`가 `beginRendering`을 대체하고, 모든 메시지에는 `version` 필드가 포함됩니다.

=== "v1.0 (후보)"

    - **`createSurface`**: 새 서피스를 만들고 카탈로그를 지정합니다.
    - **`updateComponents`**: 서피스의 UI 컴포넌트를 추가하거나 업데이트합니다.
    - **`updateDataModel`**: 애플리케이션 상태를 업데이트합니다.
    - **`deleteSurface`**: UI 서피스를 제거합니다.
    - **`actionResponse`**: 클라이언트가 시작한 액션에 응답합니다.

    v1.0에서는 `actionResponse` 메시지 유형이 새로 도입되어, 견고한 클라이언트-서버 간 동기식 RPC 기능을 지원합니다.

=== "v0.8 (레거시)"

    - **`surfaceUpdate`**: UI 컴포넌트를 정의하거나 업데이트합니다.
    - **`dataModelUpdate`**: 애플리케이션 상태를 업데이트합니다.
    - **`beginRendering`**: 클라이언트에 렌더링을 시작하라는 신호를 보냅니다.
    - **`deleteSurface`**: UI 서피스를 제거합니다.

전체 기술 정보는 [메시지 레퍼런스](../reference/messages.md)를 참조하세요.
