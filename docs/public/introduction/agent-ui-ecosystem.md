# 에이전트 UI 생태계

에이전트 기반 UI 공간은 빠르게 발전하고 있습니다. 이 페이지에서는 A2UI가 다른 주요 접근 방식들과 어떻게 관련되는지 살펴봅니다.

## 한눈에 보기

|                    | **A2UI**                                        | **MCP Apps**                                                                     | **AG-UI**                                                |
| ------------------ | ----------------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| **접근 방식**       | 선언적 컴포넌트 설계도(blueprint)                 | `ui://` URI를 통한 사전 빌드된 HTML                                                  | 백엔드와 프런트엔드를 연결하는 고대역폭 프로토콜             |
| **렌더링**          | 네이티브 컴포넌트(Angular, Flutter, Lit 등)        | 샌드박스 처리된 `iframe`                                                             | 개발자가 정의(임의의 프레임워크)                              |
| **스타일링**        | 호스트 앱이 제어: 디자인 시스템을 상속               | 격리됨: 원격 서버가 외형을 제어                                                        | 개발자가 제어: 호스트 앱의 일부                               |
| **보안**            | 선언적 데이터, 코드 실행 없음                       | 샌드박스 iframe 격리                                                                 | 여러분의 앱 안에서 실행되는 신뢰된 코드                        |
| **멀티 에이전트**    | ✅ 신뢰 경계를 넘나듦                              | ✅ 여러 MCP 서버                                                                    | ⚠️ 주로 단일 에이전트                                        |
| **크로스 플랫폼**    | ✅ 웹, 모바일, 데스크톱, 네이티브                    | ⚠️ 웹 중심(iframe)                                                                  | ✅ 프로토콜은 프레임워크에 독립적                              |

## A2UI vs MCP Apps

[MCP Apps](https://blog.modelcontextprotocol.io/posts/2025-11-21-mcp-apps/)는 UI를 **리소스**로 취급합니다: 서버가 `ui://` URI를 통해 사전 빌드된 HTML을 제공하고, 이를 샌드박스 처리된 iframe에서 렌더링합니다. 원격 통합이 모든 콘텐츠와 외형을 제어하며, 설정은 도구 호출을 통해 이루어집니다. A2UI는 **선언적 UI** 접근 방식을 취합니다: 에이전트가 컴포넌트 설계도를 보내지만, 이 컴포넌트를 어떻게 구성하고 렌더링할지에 대한 스타일링과 테마는 호스트 애플리케이션이 제어합니다. 서버가 전체 UI 경험을 소유해야 한다면 MCP Apps를, 앱에 자연스럽게 녹아드는 동적이고 크로스 플랫폼 UI를 원한다면 A2UI를 선택하세요.

## A2UI vs AG-UI / CopilotKit

[AG-UI](https://ag-ui.com/)는 실시간 상태 동기화를 통해 에이전트 백엔드와 프런트엔드를 연결하는 **전송 프로토콜**입니다. A2UI는 **UI 포맷**입니다: 무엇을 렌더링할지 설명하는 페이로드입니다. 이 둘은 상호 보완적입니다. AG-UI를 파이프로, A2UI를 콘텐츠로 사용하세요. AG-UI는 [CopilotKit](https://copilotkit.ai) 팀의 프로젝트입니다. AG-UI는 A2UI와 즉시 호환됩니다.

## A2UI vs ChatKit (OpenAI)

[ChatKit](https://platform.openai.com/docs/guides/chatkit)은 OpenAI 생태계 안에서 긴밀하게 통합된 경험을 제공합니다. A2UI는 ChatKit과 일부 설계 철학을 공유합니다: 둘 다 기본 컴포넌트 집합을 정의하고, 구성 가능한 선언적 추상화 계층을 사용합니다. A2UI는 **플랫폼에 독립적**이며, 웹·모바일·데스크톱에서 자체 에이전트 기반 서피스를 구축하는 개발자나, 신뢰 경계를 넘어 UI를 렌더링해야 하는 멀티 에이전트 시스템을 위해 설계되었습니다.

## 함께 사용하기

이러한 접근 방식들은 경쟁 관계가 아니라 상호 보완적입니다.

- **A2UI + AG-UI**: AG-UI를 전송 계층으로, A2UI를 생성형 UI 포맷으로 사용합니다.
- **A2UI + A2A**: [A2A 프로토콜](../concepts/transports.md)을 통해 A2UI 메시지를 멀티 에이전트 시스템에 전송합니다.
- **A2UI + MCP**: 향후 도입될 브리지를 통해 MCP 서버가 HTML 리소스와 함께 A2UI 설계도를 제공할 수 있게 됩니다.
