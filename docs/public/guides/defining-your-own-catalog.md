# 나만의 카탈로그 정의하기

[Basic Catalog](../../../specification/v0_9/catalogs/basic/catalog.json)는 애플리케이션을 시작하고 부트스트랩하는 데 유용하지만, 대부분의 프로덕션 애플리케이션은 자신의 디자인 시스템을 반영하는 자체 카탈로그를 정의하게 됩니다.

자체 카탈로그를 정의하면 에이전트가 범용 입력 필드나 버튼이 아니라, 애플리케이션 안에 실제로 존재하는 컴포넌트와 시각 언어만 사용하도록 제한할 수 있습니다.

## 왜 자체 카탈로그를 정의하나요?

모든 A2UI surface는 **Catalog**에 의해 구동됩니다. 카탈로그는 에이전트가 사용할 수 있는 컴포넌트, 함수, 테마를 알려 주는 JSON Schema 파일입니다.

자체 카탈로그를 정의하면 다음과 같은 이점이 있습니다.

- **디자인 시스템 정렬**: 에이전트가 애플리케이션에 실제로 존재하는 컴포넌트와 시각 언어만 사용하도록 제한합니다.
- **보안 및 타입 안전성**: 전체 카탈로그를 클라이언트 애플리케이션에 등록하므로 신뢰할 수 있는 컴포넌트만 렌더링됩니다.
- **매퍼 불필요**: Basic Catalog 같은 범용 카탈로그를 어댑터로 매핑하기보다는, 클라이언트의 디자인 시스템을 직접 반영하는 카탈로그를 만드는 것이 권장됩니다.

Basic Catalog는 하나의 예시일 뿐이며, 다양한 렌더러가 쉽게 구현할 수 있도록 의도적으로 최소한의 형태로 구성되어 있습니다.

## 동작 방식

1.  **카탈로그 정의**: 애플리케이션이 지원하는 컴포넌트, 함수, 스타일을 나열하는 카탈로그 정의(JSON Schema)를 만듭니다.
2.  **카탈로그 등록**: 카탈로그와 해당 컴포넌트 구현체(렌더러)를 클라이언트 애플리케이션에 등록합니다.
3.  **지원 여부 알림**: 클라이언트가 지원하는 카탈로그를 에이전트에 알립니다(`supportedCatalogIds`).
4.  **에이전트의 카탈로그 선택**: 에이전트가 특정 UI surface에 사용할 카탈로그를 선택합니다(`createSurface` 같은 생성 메시지 안의 `catalogId`).
5.  **에이전트의 UI 생성**: 에이전트가 해당 카탈로그에 정의된 컴포넌트 이름을 사용해 컴포넌트 메시지를 생성합니다.

## 구현 가이드

기존 컴포넌트 라이브러리에 직접 매핑되는 카탈로그를 만드는 것이 권장됩니다.

=== "Web (Lit / Angular / React)"

    웹에서 자체 카탈로그를 구현하려면 다음을 수행합니다.

    - 컴포넌트 정의를 담은 JSON Schema를 만듭니다.
    - 선택한 웹 렌더러 안에서 자체 `Component` 객체와 `Catalog` 객체를 만듭니다.
        - 에이전트에 스키마 또는 참조 ID를 제공합니다.

    _각 프레임워크별 자세한 가이드는 곧 제공될 예정입니다._

=== "Flutter"

    Flutter에서 자체 카탈로그를 구현하려면 다음을 수행합니다.

    - 위젯 속성을 설명하는 JSON Schema를 정의합니다.
    - 커스텀 렌더러를 사용해 스키마를 Flutter 위젯에 매핑합니다.

    *자세한 Flutter 통합 가이드는 곧 제공될 예정입니다.*

## 보안 고려사항

카탈로그를 정의하고 등록할 때는 다음을 지키세요.

1.  **컴포넌트 허용 목록 관리**: 카탈로그 정의에는 신뢰하는 컴포넌트만 등록하세요. 엄격히 제어되지 않는 한 임의 스크립트 실행 같은 위험한 기능을 제공하는 컴포넌트는 노출하지 마세요.
2.  **속성 검증**: 에이전트 메시지의 컴포넌트 속성이 예상 타입 제약과 일치하는지 항상 검증하세요.
3.  **텍스트 정화**: 안전한 경계가 마련되어 있지 않다면 에이전트가 제공한 정화되지 않은 콘텐츠를 그대로 렌더링하지 마세요.
