# 에이전트 (서버 측)

에이전트는 사용자 요청에 응답해 A2UI 메시지를 생성하는 서버 측 프로그램입니다.

실제 컴포넌트 렌더링은 [렌더러](renderers.md)가 수행하며, 메시지가 [전송](../concepts/transports.md)된 뒤 클라이언트에서 처리됩니다. 에이전트는 A2UI 메시지를 생성하는 역할만 맡습니다.

## 에이전트 동작 방식

```text
사용자 입력 → 에이전트 로직 → LLM → A2UI JSON → 클라이언트로 전송
```

1. 사용자 메시지를 받습니다.
2. Gemini, GPT, Claude 등 LLM으로 처리합니다.
3. 구조화된 출력으로 A2UI JSON 메시지를 생성합니다.
4. 전송 계층을 통해 클라이언트로 보냅니다.

클라이언트에서 발생한 사용자 상호작용도 새로운 사용자 입력으로 처리할 수 있습니다.

## 샘플 에이전트

A2UI 저장소에는 다음 샘플이 포함되어 있습니다.

- **Restaurant Finder**
  - 폼을 통한 테이블 예약
  - ADK 기반
- **Rizzcharts**
  - A2UI 커스텀 컴포넌트 데모
  - ADK 기반
- **Orchestrator**
  - 원격 서브에이전트로부터 A2UI 메시지를 전달
  - ADK 기반

## A2A에서 사용할 수 있는 에이전트 유형

### 1. 사용자 대면 에이전트(독립형)

사용자가 직접 상호작용하는 에이전트입니다.

### 2. 원격 에이전트의 호스트 역할을 하는 사용자 대면 에이전트

사용자 대면 에이전트가 하나 이상의 원격 에이전트를 호스트하는 패턴입니다. 사용자 대면 에이전트가 원격 에이전트를 호출하고, 원격 에이전트가 A2UI 메시지를 생성합니다. A2A에서 흔히 보이는 패턴입니다.

- 사용자 대면 에이전트는 A2UI 메시지를 변경하지 않고 그대로 전달할 수 있습니다.
- 사용자 대면 에이전트는 클라이언트로 보내기 전에 메시지를 수정할 수도 있습니다.

### 3. 원격 에이전트

원격 에이전트는 사용자 대면 UI에 직접 포함되지 않습니다. 대신 원격 에이전트로 등록되어 사용자 대면 에이전트가 호출할 수 있습니다.
